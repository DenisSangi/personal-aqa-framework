# personal-aqa-framework

UI+API фреймворк автотестирования, который Денис строит с нуля собственными руками, воспроизводя архитектуру и паттерны боевого проекта `java-selenide-pp`. Полный бриф: [STARTING-PROMPT.md](STARTING-PROMPT.md). Дорожная карта: [PLAN.md](PLAN.md). Журнал сессий: [PROGRESS.md](PROGRESS.md).

## Три цели

1. Закрыть диагностированный на EPAM-интервью (2026-07-10, не пройдено) пробел — «понимаю концепции, но не произвожу артефакт под давлением» — тренируется постройкой, а не абстрактными задачами.
2. Портфолио — публичный репозиторий с зелёным CI и опубликованным Allure-отчётом.
3. Контент для будущего веб-приложения подготовки к техническим QA-собеседованиям — каждая задача оформляется как самодостаточный урок в `curriculum/`.

## Структура

- `curriculum/` — задачи-уроки (схема: id, фаза, описание, место во фреймворке, мотивировка, теория, DoD, типичные ошибки, ссылка на реальный код).
- `theory/` — самостоятельные теоретические конспекты, на которые ссылаются уроки.
- `sessions/` — конспект каждой рабочей сессии.
- `PLAN.md` — фазовая дорожная карта.
- `PROGRESS.md` — журнал прогресса (что сделано / что слабо / что перенесено).

## Правило работы

Ты (Денис) пишешь весь продакшн-код фреймворка сам. Tech Lead ставит задачу, объясняет, ревьюит — но никогда не пишет решение за тебя.
