# curriculum/

Задачи-уроки. Один файл на задачу, создаётся в момент, когда задача реально даётся Денису (не заранее списком — см. `../PLAN.md` для дорожной карты id/названий).

## Схема файла-урока

```
# <id> — <заголовок>

**Фаза / слой:** ...
**Теги:** java / selenide / testng / rest-assured / sql / jenkins (можно несколько)

## Описание
Что построить.

## Место в фреймворке
Зависимости вверх/вниз — от чего опирается эта задача, что будет опираться на неё.

## Мотивировка
Зачем + цена отказа (в духе разделов «Без паттерна» из design-patterns.md).

## Теория
Нужные концепции + ссылка на файл в ../theory/.

## Definition of Done
Критерии приёмки.

## Типичные ошибки
Заполняется ПОСЛЕ ревью — реальные ошибки Дениса на этой задаче. Самая ценная секция для будущего веб-приложения.

## Ссылка на реальный код java-selenide-pp
Абсолютный путь к файлу(ам)-прообразу.
```

Собрана из того, что не влезло в P11-T1. **Вопрос 1** — `allure-rest-assured`: 13 API-тестов в отчёте выглядят так же, как весь проект до 19.08 (имя и статус), при том что стенд всегда отвечает 200 и прячет реальный код в теле; против подключения есть свой аргумент — P1-T2 вчера удалил ровно такие дампы из консоли как отладочный мусор, и отдельно вопрос безопасности: в form-параметрах `createAccount` идёт настоящий пароль, а фильтр пишет тело целиком (масштабнее, чем урок про `@Step("...{password}")`). **Вопрос 2** — история прогонов: без переноса каталога `history` в результаты каждый отчёт живёт сам по себе, и в CI не отличить «сломали только что» от «флакует месяц»; прецедент есть — `successfulLoginTest` регулярно ловит транзиентный CDP-таймаут и спасается retry. **Вопрос 3** — десять `assertEquals` по ячейкам таблицы корзины падают вне Selenide и скриншота в отчёт не дают; перевод на Selenide-проверки требует смены сигнатур `TableElement` (`getCellValueByRowIndexAndColumnName` возвращает `String`) и заденет `getTableHeaders()` и `TableElementTest`. **Вопрос 4** — судьба `ScreenshotOnFailureListener` (P6-T2): сейчас при падении Selenide-действия скриншот делается дважды, в отчёт и на диск. Важное замечание в постановке: замер P11-T1 показал только **факт** («`addAttachment` из `onTestFailure` теряется»), но не **причину** — прежде чем объявлять путь невозможным, стоит её выяснить; прецедент P10-T3 прямо об этом («причина разобрана, решения не нашли» ≠ «решения не существует»).
