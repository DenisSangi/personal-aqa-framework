# P1-T1 — Config Facade + порядок разрешения параметров

**Фаза / слой:** Фаза 1 — Конфигурация и инфраструктура
**Теги:** java, config

## Описание

Построить класс-фасад конфигурации (например `FrameworkConfig`) в **реальном пакете** (не default package — это первый настоящий класс фреймворка, не одноразовая заглушка; выбери и зафиксируй пакет, дальше в нём же будет жить весь `src/main`):

- Внутренний метод разрешения значения по ключу, цепочка в строгом порядке: **env var → system property → properties-файл**.
- Один `.properties`-файл в `src/main/resources/` с дефолтным значением хотя бы одного параметра (например `BASE_URL=https://automationexercise.com`), подключается через classpath.
- Наружу — простая статическая константа (`BASE_URL`), а не сырой вызов метода-резолвера, разбросанный по вызывающему коду.
- Осознанное решение, что происходит, если значение не найдено ни в одном источнике (не забыто молча).

## Место в фреймворке

Опирается на Фазу 0 (нужен рабочий `pom.xml`, класс должен компилироваться и подхватывать resources). От неё зависят все последующие слои, которым нужен URL/креды — Page Object (Фаза 4), API-сервисы (Фаза 7), БД-util (Фаза 9). Это первая реальная (не placeholder) единица кода фреймворка.

## Мотивировка

Без единой точки конфигурации каждый вызывающий код сам городит логику «откуда брать URL» — часть кода читает system property, часть — захардкодит строку, часть полезет в properties-файл напрямую. Это дублирование и рассинхрон между окружениями: локальный прогон и CI видят разные значения не потому что так задумано, а потому что логика получения URL с самого начала не централизована. Ошибка здесь (например, забытый приоритет источника) проявится не сразу, а как «на CI тест ходит не туда» — далеко от места настоящей причины.

## Definition of Done

- [ ] Класс в реальном пакете (не default package).
- [ ] Метод разрешения по ключу — именно порядок env var → system property → properties-файл.
- [ ] `.properties`-файл в `src/main/resources`, минимум один параметр с дефолтным значением.
- [ ] Наружу — простая статическая константа (`BASE_URL` или аналог), не сырой вызов резолвера у вызывающего кода.
- [ ] Продемонстрировано на ревью (можно вручную — через IDE run config с `-D`-флагом), что system property реально перебивает значение из properties-файла.
- [ ] Явно решено и видно в коде, что происходит при отсутствии значения во всех трёх источниках.
- [ ] Компилируется, существующий placeholder-тест по-прежнему зелёный.
