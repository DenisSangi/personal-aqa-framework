# Docker + Postgres — минимум для Фазы 9

Опора для [P9-T1](../curriculum/P9-T1-docker-postgres-seed.md).

## 1. Образ vs контейнер

Аналогия из Java, которую ты уже знаешь: **образ (image) — это класс, контейнер (container) — объект этого класса.** Образ — неизменяемый шаблон (файловая система + программа + настройки по умолчанию), скачивается один раз (`postgres:16-alpine` — имя:тег). Контейнер — запущенный экземпляр образа со своим состоянием; из одного образа можно поднять сколько угодно контейнеров, как объектов из класса.

`postgres:16-alpine`: `postgres` — имя образа, `16` — версия Postgres, `alpine` — вариант на минималистичном Linux (меньше размер).

## 2. Ключевые команды

```bash
docker run -d --name my-db -e POSTGRES_PASSWORD=secret -p 5434:5432 postgres:16-alpine
docker ps                # запущенные контейнеры (docker ps -a — включая остановленные)
docker logs my-db        # что контейнер пишет в стандартный вывод (первое место при диагностике!)
docker exec -it my-db psql -U postgres   # выполнить команду ВНУТРИ контейнера (тут — открыть psql)
docker stop my-db        # остановить (данные контейнера остаются)
docker rm my-db          # удалить контейнер (вместе с его данными, если нет volume)
```

Флаги `run`:
- `-d` — detached, в фоне (без него терминал «прилипнет» к контейнеру);
- `--name` — своё имя вместо случайного;
- `-e KEY=value` — переменная окружения внутрь контейнера;
- `-p HOST:CONTAINER` — проброс порта, см. ниже;
- `-v` — примонтировать папку/том хоста внутрь контейнера.

## 3. Проброс портов: `"5434:5432"` — кто есть кто

Формат всегда **`хост:контейнер`**. Postgres внутри контейнера слушает свой стандартный `5432` — это правая часть, её не меняем. Левая часть — под каким портом это видно снаружи, на твоей машине: `jdbc:postgresql://localhost:5434/...`. Несколько контейнеров могут все слушать «свой 5432» внутри — конфликтуют только ХОСТ-порты, поэтому каждому наружу выдаётся свой: локальный Postgres (если есть) держит 5432, arcade-стенд взял 5433, наш — следующий свободный.

## 4. Env-переменные официального образа Postgres

При первом старте образ сам создаёт базу и пользователя из переменных:

```
POSTGRES_DB=...        # имя создаваемой базы
POSTGRES_USER=...      # суперпользователь (по умолчанию postgres)
POSTGRES_PASSWORD=...  # обязательная — без неё контейнер не стартует
```

Ровно это видно в arcade-компоузе (`POSTGRES_DB: arcade` и т.д.).

## 5. `/docker-entrypoint-initdb.d` — авто-инициализация и её главная ловушка

Всё, что смонтировано в эту папку внутри контейнера (`.sql`, `.sh`), образ выполняет **автоматически при первой инициализации** — в алфавитном порядке файлов (отсюда конвенция имён `01-schema.sql`, `02-seed.sql`).

```yaml
volumes:
  - ./db/init:/docker-entrypoint-initdb.d
```

**Ловушка:** «при первой инициализации» значит — только когда каталог данных базы ПУСТ. Если контейнер уже создавался, повторный `docker start`/`docker compose up` скрипты НЕ перезапустит, даже если ты их изменил. Чтобы накатить заново — удалить контейнер вместе с данными (`docker compose down -v` или `docker rm` + удаление тома) и поднять заново. Симптом ловушки: «я поправил схему в файле, а в базе по-старому».

Для тестовой базы отсутствие постоянного тома — не баг, а фича: каждый пересоздание = гарантированно чистое, известное состояние данных.

## 6. docker compose в двух словах

Тот же `docker run`, но декларативно, файлом в репозитории:

```yaml
services:
  postgres:
    image: postgres:16-alpine
    container_name: aqa-postgres
    environment:
      POSTGRES_DB: ...
    ports:
      - "5434:5432"
    volumes:
      - ./db/init:/docker-entrypoint-initdb.d
```

`docker compose up -d` — поднять всё описанное, `docker compose down` — остановить и удалить (`-v` — вместе с томами). Выигрыш перед `docker run`: конфигурация версионируется в git, воспроизводится одной командой на любой машине, читается как документация.

## 7. Минимум SQL для этой задачи

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,              -- SERIAL = автоинкрементное целое
    email VARCHAR(255) NOT NULL UNIQUE, -- NOT NULL + UNIQUE = обязательное и неповторяющееся
    created_at TIMESTAMP DEFAULT now()  -- значение по умолчанию, если не передано
);

INSERT INTO users (email) VALUES ('a@b.c');
```

`psql` внутри контейнера: `docker exec -it <container> psql -U <user> -d <db>`; там `\dt` — список таблиц, `\d users` — структура таблицы, обычный `SELECT * FROM users;`, выход — `\q`.
