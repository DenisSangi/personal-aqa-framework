# java.time: LocalDateTime + DateTimeFormatter

Нужны для Задачи [P2-T2](../curriculum/P2-T2-datetime-util.md).

## `LocalDateTime` — неизменяемый value-класс

`LocalDateTime.now()` возвращает снимок текущей даты+времени (без часового пояса — если нужен пояс, есть `ZonedDateTime`). Как и все классы пакета `java.time` (`LocalDate`, `LocalTime`, `LocalDateTime`, `ZonedDateTime`), он **неизменяемый (immutable)** — любой метод вроде `.plusDays(1)` не меняет исходный объект, а возвращает НОВЫЙ:

```java
LocalDateTime now = LocalDateTime.now();
LocalDateTime tomorrow = now.plusDays(1); // now не изменился, tomorrow — новый объект
```

Это принципиально отличается от старого `java.util.Date`/`Calendar` (mutable, легко случайно испортить объект чужим кодом, которому его передали).

## `DateTimeFormatter` — форматирование по паттерну

```java
DateTimeFormatter formatter = DateTimeFormatter.ofPattern("yyyy-MM-dd_HH-mm-ss", Locale.ENGLISH);
String formatted = LocalDateTime.now().format(formatter);
```

Ключевые буквы паттерна (регистр важен, это разные вещи):

| Буквы | Значение | Пример |
|---|---|---|
| `yyyy` | год, 4 цифры | `2026` |
| `MM` | месяц, 2 цифры | `07` |
| `MMM` | месяц, короткое имя | `Jul` |
| `dd` | день месяца, 2 цифры | `27` |
| `HH` | час, 24-часовой формат | `14` |
| `mm` | **минуты** | `05` |
| `MM` vs `mm` | **месяц vs минуты** — классическая опечатка, буквы визуально похожи, но означают разное | — |
| `ss` | секунды | `09` |

## Зачем явный `Locale`

`DateTimeFormatter.ofPattern(pattern, Locale.ENGLISH)` — второй аргумент важен, когда паттерн включает буквенное имя месяца (`MMM`/`MMMM`). Без явного `Locale` форматтер возьмёт локаль по умолчанию окружения (может отличаться между твоей машиной и CI-сервером) — на другой локали `"Jul"` может стать `"июл"` или чем-то ещё, и тест, ожидающий английское имя месяца, начнёт падать не из-за бага, а из-за окружения, на котором он запущен.

## `DateTimeFormatter` и потокобезопасность — параллель с сегодняшней темой `Random`

Старый `java.text.SimpleDateFormat` был **mutable и НЕ потокобезопасен** — один и тот же экземпляр, используемый из нескольких потоков параллельно, мог отдавать испорченные результаты (классическая производственная ловушка Java до `java.time`). `DateTimeFormatter`, наоборот, неизменяем и потокобезопасен — его можно спокойно завести один раз как `static final` поле и переиспользовать из любого количества потоков одновременно, без риска, который был у `SimpleDateFormat`. Та же логика, что и разница `Random` vs `ThreadLocalRandom` из [P2-T1](../curriculum/P2-T1-random-generators.md): mutable общее состояние = проблема при параллелизме, immutable = нет.

## Форматирование "сейчас" под разные паттерны — одна функция, разные строки

Смысл задачи P2-T2 — не строить весь калейдоскоп методов из референса (парсинг чужих дат, сравнение зон, арифметика "через N дней"), а решить узкую практическую задачу: получить текущую дату/время как строку в НУЖНОМ формате, чтобы приклеить её к имени тестовой сущности и гарантировать уникальность между прогонами:

```java
String suffix = LocalDateTime.now().format(DateTimeFormatter.ofPattern("ddMMyyyyHHmmss"));
String userName = "user_" + suffix; // например "user_27072026143512"
```
